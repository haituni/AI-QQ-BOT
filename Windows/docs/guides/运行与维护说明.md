# 运行与维护

这是面向一台 Windows 电脑、一个机器人 QQ 账号的本地应用。Python 和应用数据保存在本目录内；Docker Desktop 的镜像和虚拟磁盘由 Docker Desktop 管理，不依赖开机自启服务。控制台不是面向公网的多人 SaaS；请保持 8765、3001、6099 仅用于本机。

## 日常使用

1. 双击「栖.app」，填写「账号与连接」并保存。测试按钮使用已保存的密钥，测试会消耗一次真实模型调用。
2. 在「运行与数据 → 服务与诊断」安装或启动 QQ 接入。任务会持续显示进度，最多运行 30 分钟；失败或中断后可以重新执行。与命令脚本共用操作锁，避免并发操作虚拟机。
3. 在「账号与连接」打开扫码窗口，程序自动认证并展示二维码，无需接入 Token。回到总览检查账号、密钥、QQ 登录、登录账号核对、会话授权五项。模型密钥检查只证明已填写，不代表余额、网络和模型可用；需要手动连接测试。
4. 添加群聊或私聊后仍默认未授权。展开「编辑设置」，确认角色、授权、主动聊天时段并保存。可以按名称、号码、类型和授权状态筛选。
5. 需要临时静音时，在总览暂停。管理员私聊仍可管理；QQ 接入停止与聊天暂停是两个独立操作。
6. 完整关闭可选择菜单栏「停止机器人并退出」，或点击界面左下角「关闭机器人」。等待关闭完成后再删除目录。

刷新状态不会覆盖正在编辑的账号和会话草稿。后台发现设置版本变化会提示；保存按草稿原版本检查，拒绝覆盖其他操作。发生冲突后可复制需要的内容，再使用「重新载入 / 放弃草稿」读取最新配置。

## 诊断和回执

- 总览显示最近 24 小时模型请求成功率、平均耗时、等待数与服务运行时间。Token 数据来自模型返回的 usage；不推算费用，没有返回 usage 的请求计 0 Token。调用次数仍在预算中保守计入。
- 模型 HTTP 请求统一排队，同时最多处理 3 个；聊天和管理请求优先，记忆整理和自主活动的后台请求最多占一个名额。等待队列最多 100 个请求，本轮总时限 180 秒包含排队和工具处理；达到队列或时限上限仍可能取消。排队后会重新检查设置、记忆代次与工具权限；连续 3 次 HTTP、网络或 JSON 请求失败后，暂时阻断新请求 1～5 分钟。到期后由后续请求探测恢复，未自动重复请求。修改并保存密钥或模型会重置保护状态。
- QQ 连接断开后以最长约 31 秒的退避间隔重新连接。75 秒没有协议消息会关闭失效连接并重连。重连不会重发历史消息。
- 发送回执的「接口已确认」只表示 OneBot 返回成功，不代表对方已读。「结果不确定」包括超时、断线、发送过程中退出，以及上次进程终止时尚未得到回执。为避免重复发送，这些消息不自动重发。管理员指令反馈也有回执。
- 运行记录最多 500 条，回执最多 3000 条（界面显示最近 50 条），模型请求指标保留 30 天。记录不包含消息正文或密钥。环境任务日志只保留最近 80 行，并隐藏当前密钥及常见 token 字段。
- 「导出诊断」只包含检查结果、队列数量、请求统计与回执数量，不含账号号码、聊天内容、角色设定或密钥。
- 管理接口错误带记录编号。最近 200 条异常另保存文件名、函数名、行号和异常类型，不保存异常文本、局部变量、源代码行或绝对路径。认证后的控制台展示最近 5 条位置记录；导出诊断仍不包含这些记录。
- QQ 连接、聊天调度、数据维护和记忆整理均有后台监督；循环意外退出后按 1～60 秒退避重新启动。它不重试发送消息，也不能在整个 Python 进程退出后自动拉起服务。

## 备份与恢复

「立即备份」在工作线程通过独立 SQLite 连接执行在线备份与完整性检查，同时保存配置和 SHA256 清单；正常聊天可以继续，备份期间配置和管理写操作暂不可用。恢复和数据库压缩也在工作线程进行，恢复期间阻止消息处理和管理写入，避免并发修改。浏览器取消请求不会提前释放维护锁。文件在 `backups/snapshot-…/`，目录权限 700，数据文件权限 600。它是完整快照，包含密钥和聊天内容，没有加密。不要公开分享。

实际服务启动时会检查备份；运行中每小时再检查，距最近一份完整快照至少 24 小时后自动备份。只保留最新 8 份，包含手动、每日与恢复前快照。备份不包含虚拟机磁盘、QQ 扫码状态、程序依赖和源码。同盘备份不能防止磁盘故障。若需要异地恢复，请在停止全部后将整个目录复制到你信任的存储。

恢复前先暂停，等待所有正在处理的请求和环境任务结束。程序先检查文件哈希及数据库，再创建当前状态的保护备份。恢复角色、会话设置、聊天记录和长期记忆；保留**当前**管理员、机器人账号、API Key、接入密钥、管理登录密钥、累计调用额度、消息去重与审计。恢复后保持暂停，核对配置再恢复运行。历史快照可能包含此前已撤销的会话授权，所以不能自动恢复发送。

恢复使用数据库事务日志协调配置：提交前失败会回滚数据库且不修改配置；提交后配置尚未落盘时断电，下次启动在加载配置前重放已提交配置，并保持暂停。配置写入失败时当前服务进入维护保护，需要重启后完成恢复。若磁盘损坏或无法写入，仍需修复存储或使用保护备份。数据库和备份版本高于当前程序时会拒绝打开，避免旧程序误改新数据。

清除会话记忆只清当前数据库，不会清已有备份、QQ 平台记录或模型服务已处理的数据。导出会话记忆包含该会话最多 2000 条本地消息和长期摘要，请同样妥善保管。

## 已知运行边界

- QQ 使用非官方接入。扫码验证、上游协议变化、风控和账号限制无法由本程序承诺消除。界面成熟不等同于官方支持或可用性 SLA。
- 电脑休眠、断网和进程退出期间不服务；没有系统开机自启和进程外自动拉起。重开启动脚本即可恢复服务。
- 当前消息队列在内存中，单会话最多 100 条。已接收但尚未处理的排队消息在进程崩溃时可能丢失；不承诺所有消息必达或恰好一次处理。队列满会记录告警。不要把它用作财务通知或其他不可丢失事件的唯一通道。
- 主动聊天状态和每日上限持久化，不补发停机期间错过的检查。多个到期会话共享最多 3 个执行位，避免单个慢请求阻塞所有会话。
- 本机管理密钥等同于管理权限；持有该密钥的人可以查看本地记忆、修改配置和恢复备份。认证会话最长 12 小时，重启管理服务后需重新登录。
- 当前验证以本机模拟的 QQ 和模型接口为主；真实账号、真实 DeepSeek 的联调验收和长时间运行观察需在用户本地填写配置、扫码后完成。

## 发布前验收建议

用专用测试 QQ 与测试群完成授权、撤权、掉线重连、主动时段、密钥失效恢复、备份恢复的实际演练，并连续观察运行。记录观察期、真实成功率和上游版本后，再决定是否用于付费业务。自动测试通过不能替代这一步。

模型工具详见 [工具菜单使用说明](工具菜单使用说明.md)。高级环境诊断使用 `.venv/Scripts/python.exe scripts/runtime.py status`，无需全局 limactl。

长期原文、压缩记忆、磨合状态和 Token 日汇总均在同一 SQLite 中；归档不会随近期 2000 条窗口删除。数据库随使用增长，可在管理界面查看用量并按需备份。


### 分会话 Token 用量

概览的 Token 用量区域可选择全部会话、某个私聊/群聊或历史未归属/系统调用，时间范围支持今日、7/30/90天。明细列出请求数、输入、输出和总Token；输入缓存和用途沿用API实际返回字段。工具多轮模型请求及后台记忆整理归属原会话，系统连接测试与沙盒试聊独立统计；工具服务自身费用不包含在模型Token中。此前未记录会话维度的历史无法追溯，不做估算分摊。

管理员普通私聊直接聊天；设置修改仍可自然表达，但需明确说出授权、开启主动聊天、修改角色等管理意图。含糊的接话不会延续上一条管理操作。

## 数据增长与源码版本

数据库使用 WAL，日常短读写仍由主线程执行；完整备份、恢复和压缩移到工作线程。清除记忆执行逻辑删除并标记待压缩，待标记跨重启保存；服务每小时在暂停且无请求时尝试压缩。该操作不承诺抹除已有快照或进行磁盘取证级擦除。控制台显示数据库和 WAL 大小；数据库超过 1 GB、磁盘剩余不足 1 GB 会提示，备份空间不足时拒绝创建，不自动删除长期原文。

本地 Git 记录源码变化，不设远程。运行环境、密钥配置、聊天数据、日志、备份、应用构建产物和个人角色材料均被忽略。源码版本与数据快照分别管理；回退源码不能代替恢复数据库，较旧程序也可能拒绝新版数据库。
