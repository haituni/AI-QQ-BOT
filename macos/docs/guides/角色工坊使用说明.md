# 角色工坊

这是面向 QQ 的角色与提示词工作台。参考 SillyTavern 的角色卡、用户人设、世界书和提示词管理思路，使用同一套编译器构建 QQ 聊天请求和本地预览。它不运行酒馆本体，也不宣称兼容所有酒馆插件。

## 从一个角色开始

1. 进入「角色工坊 → 角色卡」，选择现有角色或点击书架上的 ＋。可以复制角色后再改。
2. 分别填写人物描述、性格与表达方式、场景与关系、开场白和对话示例。作者说明只随角色卡展示、导出，不进入模型。
3. 在「用户人设」中写下希望角色了解的称呼、身份、偏好和关系。`{{user}}` 使用人设名称，`{{persona}}` 使用人设描述。
4. 在顶部选择默认角色、用户人设和生成预设，点击「保存工坊设置」。切换左侧书架只是在选择编辑对象，不会自动更换默认角色。
5. 在「会话与主动聊天」中，可以给每个群或私聊单独绑定角色、人设和预设；选择「跟随工坊默认」则继承顶部设置。**角色绑定不会授权会话**，仍需独立开启回复和主动聊天。

内置两个可编辑的起点：「栖」适合日常 QQ 聊天；「灯下的旅人」附带虚构雨城书店背景，用来演示叙事与世界书。内置「日常 QQ」和「沉浸叙事」两个生成预设。人物背景与示例不是你真实发生过的经历。

原先那一段性格文字保存在「会话记忆 → 全局补充规则」，会作为管理员补充进入角色定义；单会话原有性格文字优先覆盖这一补充。可清空补充，让角色卡决定人物语气。

## 角色卡导入和导出

顶部选择导入类型，再点击「导入」选择本地文件：

| 类型 | 支持范围 |
| --- | --- |
| 角色卡 JSON | Character Card V2 常用字段；也可读取旧版平铺 JSON |
| 角色卡 PNG | `chara` / `ccv3` 文本元数据与本地 PNG 头像；最大 3 MB、4096×4096 |
| 世界书 JSON | V2 内嵌世界书；酒馆 `entries` 数组或对象、常见关键词和注入字段 |
| 生成预设 JSON | 本项目预设完整格式；酒馆主提示词、后置指令、常见采样值与已支持的模块顺序 |
| 整个工坊 JSON | 本项目角色、用户人设、预设、世界书和默认选择；不包含账号密钥或真实聊天记录 |

导入结果先放入**草稿**，检查字段和兼容性提示后保存。没有自动启用角色内置系统提示词或运行脚本，也不会拉取远程头像、扩展或资源。

单张角色可以导出 V2 JSON 或带角色数据的 PNG。导出时合并角色关联世界书；PNG 优先保留已上传头像，没有头像时使用一个最小占位 PNG。PNG 总大小超过 3 MB 时提示改用 JSON。备选开场白、作者、版本、标签、创作者说明和未知扩展元数据会保留；扩展元数据只作为数据保存。

单项导出使用已保存内容；「导出工坊」可以直接备份当前未保存的完整草稿。世界书、预设和工坊 JSON 导入最大 11 MB，工坊有效数据总量最大 10 MB。

V3 卡只读取通用定义，并提示资产包等专有功能不受支持。酒馆脚本、复杂宏、向量检索、概率触发、正则关键词、复杂次关键词逻辑和插件专有采样器不执行；导入时会尽可能提示相关限制。不要把某张卡能导入理解为其所有插件行为都已复现。

## 世界书

每本书由多个条目组成，可分别绑定到全局、角色或会话。未绑定的书不参与匹配。

- 主关键词：在预设指定的最近消息范围内，命中任意一个字面关键词即可触发，默认不区分大小写。
- 次关键词：勾选双条件后，还需命中至少一个次关键词。可选大小写敏感和完整单词匹配；中文短语通常使用默认的子串匹配更合适。
- 常驻：无需关键词始终参与注入，仍受条目开关、模块开关和预算限制。
- 优先级：在每一轮触发候选中从高到低分配字符预算。预算不足的条目被跳过，检查器显示原因。
- 递归：已成功注入的正文可以继续触发其他条目，轮数由预设限制。因预算不足而未注入的正文不会继续触发其他条目；可为条目关闭递归参与。
- 注入位置：角色定义前、角色定义后、历史前、历史后，或历史中的指定深度。深度 0 表示最新消息之后，1 表示最新消息之前；以真实历史消息计数，不把其他深度注释计入。

条目标题和关键词用于管理及匹配，真正进入模型的是正文，因此应把事实写完整。关键词会扫描最近的用户和角色文字；不扫描其他会话，也不会自动扫描你的本机文件。

## 提示词与生成预设

可分别配置主提示词、后置指令、Author's Note、注释深度、Temperature、Top P、最大输出 Token、回复字符上限、总上下文预算、世界书预算、扫描条数和递归轮数。

提示词模块可以上下移动、开启或关闭。聊天历史和程序运行协议始终保留；当角色定义、世界书和固定提示词本身超过预算时会明确报错，避免悄悄丢掉核心定义。可裁剪时，先移除最旧历史，再减少示例，尽量保留最新输入。

预算以**字符**计，不是准确 Token 数。生成参数中的最大输出 Token 也包含 JSON 决策和记忆摘要，不能全部视作对外回复长度。模型关闭思考模式；建议主要调整 Temperature 或 Top P 中的一项。

预设可以选择是否优先使用角色卡自带的系统提示词和后置指令。默认关闭，开启后可用 `{{original}}` 在角色指令中嵌入预设原文。无论使用哪个预设，角色卡都不能通过提示词改变会话授权、获取密钥或调用本机命令。

支持的模板宏：

```text
{{char}}          当前角色名称
{{user}}          当前用户人设名称
{{description}}   角色描述
{{personality}}   角色性格
{{scenario}}      场景
{{persona}}       用户人设描述
{{date}}          北京日期
{{time}}          北京时间
{{weekday}}       星期
{{original}}      角色覆盖提示词中的原预设内容
```

未知宏保留为文字并在检查器中提示。宏只在管理员设置的模板中展开，用户聊天中的 `{{char}}` 等内容不会被当作程序指令或脚本执行。

## 试聊与提示词检查器

在角色档案下方点击「带着这个角色去试聊」，或直接进入「试聊与提示词」。角色、人设和预设可以临时选择，使用当前草稿，不必先覆盖真实 QQ 配置。

- **预览 · 不调用模型**：免费地编译当前输入，显示模块顺序、字符数、世界书命中、预算跳过原因、裁剪数量和完整模型消息 JSON。不会访问 DeepSeek。
- **发送试聊**：调用已配置的 DeepSeek API，计入每日调用限制；保留当前网页里的试聊上下文。
- **重新生成**：对最近一条用户消息再生成一次，替换上一条角色回答，不向 QQ 发送。
- **模拟主动搭话**：检查主动消息场景下的风格与回复决策。模型仍可选择保持安静。
- **参照会话**：可显式选择一个已配置会话并勾选引入其记忆。默认是独立试聊，不引入任何真实会话记忆。
- **查看所选会话已保存的真实上下文**：使用服务端已保存的角色绑定、生成预设和真实会话历史，不混入未保存草稿。

试聊不发送 QQ 消息、不写真实会话记录、不更新真实长期摘要。刷新网页后试聊历史丢失，真实会话记忆不受影响。角色开场白会展示为试聊的起始消息，在真实 QQ 中只作为首轮风格上下文，不会因编辑或切换角色而自动发送。

注意：看见提示词正确注入，不代表模型必然遵循全部细节；实际风格需要你配置密钥后通过试聊判断。

## 管理 QQ 的自然语言切换

管理者可在私聊中选择工坊中已有的角色、人设和预设，例如：

```text
把默认角色切换成灯下的旅人
把默认预设切换成沉浸叙事 · 留白与细节
让群 123456789 使用栖这个角色
让私聊 987654321 跟随默认角色
```

解析器只能选择已有标识，不能通过这些命令重写整个角色库。完整卡片、世界书和预设编辑在本机界面完成。原有「把性格改成……」指令修改管理员的全局补充规则。

## 保存与恢复

所有资料仍在当前目录的 `config/settings.json`。从旧版本首次启动时，会先创建 `config/settings.before-character-studio.json`，再补充角色工坊字段；账号、密钥、会话授权和原有性格文字保留，聊天数据库不迁移、不清空。

未保存的角色编辑会标记为草稿。离开页面时浏览器会提醒；「撤销未保存修改」可恢复最近保存的角色库。「移出草稿」在保存前可以这样恢复，已绑定真实会话的项目需要先解绑才能删除。

删除整个 bot 的流程不变：先运行「停止全部.command」，再删除项目文件夹。
