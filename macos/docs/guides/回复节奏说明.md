# 自然回复节奏

已为现有会话默认开启，可在「会话与主动聊天 → 编辑设置」中关闭或调整首条目标等待上限（默认45秒，可设2～120秒）。

模型在同一次聊天决策里决定每个气泡的等待时间，不增加专门规划等待时间的模型调用。首条目标从最后一条消息收到时起算，模型与工具处理耗时计入其中；例如目标8秒、模型处理了5秒，就再等约3秒。若处理本身超过目标，完成后尽快发送，不重复等一遍。上限限制的是计划等待，不保证模型和网络一定能在该时间内完成。

后续气泡由模型各自安排1～12秒间隔。紧要的接话倾向及时回复，阅读、思考、角色当下状态与最近实际发言间隔帮助模型决定节奏，不固定使用同一间隔。不存在真正的QQ输入状态模拟，也不会向聊天发送“正在等”“正在打字”等内部说明。

## 新消息与取消

你继续发来消息时，正在生成或等待的旧回复会失效，已经排队的普通消息合并后重新判断；已经发送成功的气泡保留，不重复发送。重新判断可能带来额外模型调用。管理指令不额外加入人为等待；正在进行的模型请求仍需完成或超时后才能处理后续工作。

等待期间不占模型调用并发名额，各会话等待互不阻塞。暂停、撤销授权、清除记忆、配置变化或断开连接会阻止未发送内容。主动联系也执行气泡间隔，等待结束后重新检查发送时段和权限，整个多气泡主动联系只计一次日上限。

待发计划仅在当前服务进程中存在，不跨退出、重启或已检测到的断线补发，避免恢复后突然发送过时的话。由于系统调度与网络耗时，实际发送时间可能比计划更晚。

## 查看和验收

会话卡片显示等待中的预计发送时间。角色工坊独立试聊直接展示结果，不实际等待；检查器显示模型的时间计划，QQ发送才执行该计划。仅供管理端查看，不进入聊天气泡。

模型漏填或填错时间字段时，不额外付费重试，使用首条6秒、后续2秒的默认计划并限制在会话上限内；关闭节奏时首条不人为等待，后续恢复0.8秒间隔。默认策略是兼容兜底，正常情况由模型给出计划。
